# forecast4 の OMW 鏡相手14敗の分析

対象は `screen.json` の `forecast4` 対 `omw` の14行。各seedのseat交換を同じ条件で再実行し、OMW対OMWをcontrolとして比較した。再現データは `loss-diagnostics.json` に保存した。

## まず分けるべき二種類

- 994003, 994007, 994011, 994013, 994026, 994028: 6 seed・12行は、OMW対OMWがdrawなのにforecast4が負けた真の回帰。
- 994022, 994031: 2行は依然として負けだが、OMW対OMWのcontrolよりは改善している。forecast4固有の回帰とは言いにくい。

真の回帰6 seedの差は `-13`〜`-522` cashで、処理エラーではない。全14試合は完了し、forecast予測エラーは0だった。

## 観測された原因

追加されたSELLは主にMILK、WOOL、STRAWBERRYで、controlの予定より1〜2ターン早いものが多い。たとえば994003では、MILK 3 unitsをstep 356（価格150）で売り、controlはstep 358（価格154）で売っている。994007では、MILK/WOOL/STRAWBERRYの前倒しがまとまって発生し、994013では最終的なSTRAWBERRY売却量がcontrolより27 units少なくなった。

候補コードは、遠い予測が成立した場合にも、予測された直近ロットだけではなく、step後48ターンの予定SELLを合計して `qty` を決めている（`main.py` の `_v92_predict`）。つまりforecast4の新しいトリガーに、既存PREDICTの大きな前倒し数量がそのまま接続されている。

その結果、

1. 価格が同じでも市場在庫を早く積み増して相手の販売価格・行動を変える。
2. 商品ごとのSELL順序が変わり、別商品の予定SELLや購入注文と競合する。
3. seedによってはMILK/WOOLの前倒しがSTRAWBERRY等の売却量を押し出す。

という市場外部性が出ている。FEEDや実行timeoutが主因ではない。

## 判定

forecast4の「4ターン先まで見る」判定自体はscreen全体では有効だったが、遠いシグナルに対して48ターン分を一括前倒しする数量制御が強すぎる。次の実験では、forecast4分岐だけを直近4ターンの予測数量に制限するか、少なくとも価格が基準価格を下回る場合は発火を抑えるべきである。原版OMWは変更せず、数量制限を別候補として再評価する。
