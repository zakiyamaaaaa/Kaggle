# Kaggriculture エンジン仕様

この文書は、Kaggriculture エージェントを実装・検証するためのローカル仕様書です。
説明用 README ではなく、インストール済みの `kaggle-environments==1.32.7` の実装を一次情報としています。

- 対象環境: `kaggriculture`
- 対象バージョン: `kaggle-environments==1.32.7`
- 確認日: 2026-09-12
- 一次情報:
  - `.venv/lib/python3.12/site-packages/kaggle_environments/envs/kaggriculture/kaggriculture.py`
  - `.venv/lib/python3.12/site-packages/kaggle_environments/envs/kaggriculture/kaggriculture.json`

> バージョン更新時は、この文書よりインストール済みエンジンのコードを優先する。

## 1. ゲームの概要

2人のプレイヤーが、それぞれ独立した10×10の農場を運営する。ゲーム終了時の所持金が報酬になり、最終的には相手より多くの所持金を持つことが目的となる。

| 項目 | デフォルト値 |
|---|---:|
| プレイヤー数 | 2 |
| `episodeSteps` | 720 |
| 1日あたりのターン数 | 24 |
| ゲーム内日数 | 30日 |
| 開始所持金 | 3,000 |
| 盤面 | 10×10 |
| Shed容量 | 100 |
| 1ターンの市場注文上限 | 10 |
| 1 actionの基本制限時間 | 1秒 |
| 初期overage time | 60秒 |

初回呼び出しは環境の初期化に使われる。実際に行動を返す観測は通常719回で、最終報酬は終了時の `farm.money` である。Shed、作業員の所持品、未収穫物などに独立した評価額は付かない。

## 2. 1ターンの処理順

各ターンは次の順番で処理される。

1. 各プレイヤーのfarmerとhandsの行動を処理
2. 両プレイヤーの市場注文を処理
3. Town Centerと解放済みShopが市場在庫を消費
4. 寿命を迎えた作物を減衰
5. そのターンが日の最終ターンなら日次更新
6. `day` と `hour` を次ターンへ進める
7. 最終stepならstatusを`DONE`にして、所持金をrewardへ設定

同じターン内では、farmerの行動が先に、その後 `hands` 配列の順番で処理される。

### 日次更新の順番

日の終了時には、次の処理が行われる。

1. 作物の水やり状態、継続収穫、枯死を更新
2. 動物の給餌状態、生産、CARE bonus、逃亡を更新
3. 空いている解放済みtileに雑草を抽選
4. farmerとhandsの所持品をShedへ移動
5. farmerを初期位置へ戻す
6. 全handsを削除
7. 当日の雇用回数を0へ戻す
8. 条件を満たす日にShopを1件解放

Shed容量を超えた所持品は、日次回収時に破棄される。

## 3. 観測

actionへ渡される主な観測は次のとおり。

| フィールド | 公開範囲 | 内容 |
|---|---|---|
| `player` | 自分のみ | 自分のplayer ID |
| `farms` | 共有 | 両者の盤面、所持金、位置、土地、雇用数 |
| `private` | 自分のみ | Shed、種、各作業員の所持品 |
| `market` | 共有 | 商品ごとの市場在庫と現在価格 |
| `town` | 共有 | 解放されたShopのリスト |
| `day` | 共有 | 0始まりの日番号 |
| `hour` | 共有 | 0始まりの日内ターン番号 |

相手のShed、種、作業員ごとの所持品は見えない。相手の所持金、盤面、farmer・handsの位置は見える。

## 4. action形式

```python
{
    "farmer": ["PASS"],
    "hands": [],
    "market": [],
}
```

- `farmer`: 主作業員の操作を1件
- `hands`: 各handに対応する操作。index 0が最初のhand
- `market`: 市場注文。先頭から最大10件まで処理

不正な形式、条件を満たさない操作、存在しない対象への操作は、原則として例外を出さずsilent no-opになる。

## 5. 盤面と土地

10×10の盤面は5×5の4区画に分かれる。

| 区画 | 初期状態 | 解放価格 |
|---|---|---:|
| NW | 解放済み | - |
| NE | LOCKED | 1,000 |
| SW | LOCKED | 2,000 |
| SE | LOCKED | 4,000 |

`BUY_LAND` は必ずNE、SW、SEの順で解放する。任意の区画を指定することはできない。

### Shedアクセス地点

Shed自体は `tiles` 内に存在しない。10×10盤面でShed操作が可能な地点は次の4マスである。

```text
(4,4), (5,4), (4,5), (5,5)
```

座標は `(x, y)` で、xは右方向、yは下方向に増える。初期farmer位置は `(4,4)`。

移動はLOCKED tile上にも可能だが、LOCKED tileで通常のtile操作はできない。Shed操作だけはLOCKED判定より先に処理されるため、4つのアクセス地点すべてから利用できる。

## 6. farmer・handの操作

| 操作 | 引数 | 成功条件・効果 |
|---|---|---|
| `NORTH/SOUTH/EAST/WEST` | なし | 盤外でなければ1マス移動 |
| `PASS` | なし | 何もしない |
| `PICKUP` | item, `[n=1]` | Shed隣接時、Shedから所持品へ移動 |
| `DROP` | なし | Shed隣接時、所持品を可能な限り全てShedへ移動 |
| `PLACE` | item, `[n=1]` | 動物の配置、またはShedへの指定数量の格納 |
| `PLANT` | crop | 空tileで種を1個消費して植える |
| `WATER` | なし | 現在tileの作物を当日水やり済みにする |
| `HARVEST` | なし | 現在tileの収穫物を作業員の所持品へ移動 |
| `FERTILIZE` | なし | 肥料を1個消費し、当日から3日間有効化 |
| `DIG` | なし | 作物、雑草、空のCOOP/PASTUREを除去 |
| `BUILD_COOP` | なし | 空tileにCOOPを建設。建設費なし |
| `BUILD_PASTURE` | なし | 空tileにPASTUREを建設。建設費なし |
| `FEED` | なし | Wheatを1個消費して動物を当日給餌済みにする |
| `CARE` | なし | 動物を当日CARE済みにする |
| `COLLECT_FERTILIZER` | なし | 取得可能な肥料を1個、作業員の所持品へ移動 |

### 重要な境界条件

- 種は `private.seeds` にあり、Shedや作業員の所持品を経由しない。
- `PLANT` は同一ターン内の同一作物の要求数が種数を超えると、その作物の全 `PLANT` が取り消される。
- `PICKUP` の要求数がShed在庫を超える場合は、存在する数量だけ取得する。
- `DROP` はShedに入りきらない分も作業員の所持品から消える。
- `DIG` で動物が入っているCOOP/PASTUREは壊せない。
- COOPにはGOOSE、PASTUREにはCOWまたはSHEEPだけを配置できる。
- `PLACE <animal>` は動物を作業員が所持している必要がある。

## 7. 作物

| 作物 | 種価格 | 初回収穫可能日 | 最大収量日 | 再生間隔 | 収量上限 | 継続型 |
|---|---:|---:|---:|---:|---:|---|
| WHEAT | 10 | 2 | 4 | - | 6 | No |
| CARROT | 20 | 2 | 3 | - | 4 | No |
| TOMATO | 50 | 8 | 8 | 1日 | 4 | Yes |
| STRAWBERRY | 100 | 10 | 10 | 2日 | 4 | Yes |
| MELON | 80 | 10 | 12 | - | 6 | No |

日数は `current_day - planted_day` で計算する。

### 水やりと雑草化

- 植えた直後は `consecutive_unwatered=1` で始まる。
- 植えた当日に水をやらない場合、最初の日次更新で2となり、即座に雑草化する。
- その後も1日水をやらないだけなら生存するが、2日連続で未給水になると雑草化する。
- 1日に複数回 `WATER` しても、最初の1回だけが有効。

### 単収穫作物

WHEAT、CARROT、MELONは植えた時点で `yield_units=1` を持つ。次の期間に行う各日の水やりで収量が増える。

| 作物 | 水やりで収量が増えるage |
|---|---|
| WHEAT | 2〜4 |
| CARROT | 2〜3 |
| MELON | 6〜12 |

通常は1回の有効な水やりで `+1`、肥料有効中は `+2`。ただし収量上限を超えない。初回収穫可能日より前の `HARVEST` は無効。収穫するとtileは空になる。

### 継続型作物

TOMATOはage 8から毎日、STRAWBERRYはage 10から2日おきに、日次更新で収量を発生させる。生産回数はそれぞれ最大4回で、tileが保持できる収量も最大4。

- 当日水やり済みかつ肥料が有効なら、その生産は `+2`
- それ以外は `+1`
- 水やりを忘れても、その日の生産自体は `+1` 発生し得る
- ただし未給水が2日連続すると、生産処理より先に雑草化する
- 最終生産後は寿命が設定され、以後2stepごとに未収穫量が1ずつ減る
- 減衰で `yield_units<=0` になると雑草化する

### 肥料

`FERTILIZE` をday `d`に実行すると、`d`, `d+1`, `d+2` の3日間有効。肥料は作物tile上で、作業員が肥料を所持している場合だけ使える。

肥料は収量発生日または単収穫作物の収量加算期間に重ならないと効果がない。肥料そのものは市場で売却できる。

## 8. 動物

| 動物 | 購入価格 | 必要施設 | 初回生産日 | 生産間隔 | 保持上限 | 生産物 |
|---|---:|---|---:|---:|---:|---|
| GOOSE | 300 | COOP | 4 | 1日 | 4 | EGG |
| COW | 400 | PASTURE | 8 | 2日 | 6 | MILK |
| SHEEP | 500 | PASTURE | 6 | 3日 | 6 | WOOL |

日数は `next_day - placed_day` を基準に日次更新で判定する。

### 給餌と逃亡

- `FEED` はWheatを1個消費する。
- 同じ日に2回以上給餌しても、最初の1回だけが有効。
- 2日連続で給餌されないと動物は逃げ、空のCOOP/PASTUREだけが残る。
- 日次更新後、`fed_today` はFalseへ戻る。

### CARE bonus

- CAREしただけではbonusは増えない。
- 同じ日に `CARE` と `FEED` の両方が成功すると、日次更新で `pending_care_bonus += 1`。
- 生産日に給餌されている場合のみ、蓄積bonusがその日の基本生産1個に加算される。
- 生産日の給餌がない場合、蓄積bonusは消費されず、更新後に0へリセットされる。
- CAREによる追加分を含めても、動物ごとの保持上限を超えない。

実装順の都合上、生産日のCAREはその日の生産ではなく、次回以降の `pending_care_bonus` に入る。

### 肥料の回収

生存している動物は毎日の日次更新後に肥料を1個取得可能な状態になる。未回収のまま次の日になっても、保持されるのは真偽値だけなので複数個には蓄積しない。

## 9. 作業員の雇用

`HIRE` は市場注文として処理される。1日のn回目の費用はFibonacci列に従う。

```text
1, 1, 2, 3, 5, 8, 13, ...
```

デフォルトの倍率は1。雇用費を払える場合、handはShedアクセス4地点のうち占有数が最小の場所に出現し、同数ならNW、NE、SW、SEの順で選ばれる。

handsは日をまたいで残らない。日の終了時に所持品をShedへ移して全員削除される。翌日は雇用回数と費用列がリセットされる。

## 10. Shedと在庫

Shed容量100には、作物、生産物、肥料、購入済み動物が含まれる。種は含まれない。

- 市場で買ったWheat、Fertilizer、動物は直接Shedへ入る。
- Shed満杯時は `BUY_PRODUCT` と `BUY_ANIMAL` が失敗する。
- 売却対象はShed内の商品だけ。作業員が持ったままの商品は売れない。
- 日末に作業員の所持品が自動回収される。
- 日末回収で容量を超えた分は消滅する。

## 11. 市場

市場在庫は全商品10,000、初期価格は下表から始まる。

| 商品 | 基準価格 | 不足側曲線 | 過剰側曲線 |
|---|---:|---|---|
| WHEAT | 25 | sqrt | log |
| CARROT | 35 | hinge | sqrt |
| TOMATO | 60 | hinge | sqrt |
| STRAWBERRY | 120 | sqrt | linear |
| MELON | 250 | log | square |
| EGG | 50 | hinge | log |
| MILK | 160 | sqrt | linear |
| WOOL | 200 | log | square |
| FERTILIZER | 100 | linear | linear |

価格の下限は1。市場在庫が10,000未満なら不足側の曲線で値上がりし、10,000を超えると過剰側の曲線で値下がりする。CARROT、TOMATO、EGGの `hinge` は不足が閾値を超えると二次的に急上昇する。

### 市場注文

| 注文 | 対象 | 価格・制約 |
|---|---|---|
| `BUY_SEED item n` | 全作物 | 固定の種価格。`seeds`へ入る |
| `BUY_PRODUCT item n` | WHEAT, FERTILIZERのみ | 動的価格。Shedへ入る |
| `BUY_ANIMAL item n` | GOOSE, COW, SHEEP | 固定価格。Shedへ入る |
| `SELL item n` | 全PRODUCTS | 動的価格。Shedから売る |
| `HIRE` | - | 当日のFibonacci費用 |
| `BUY_LAND` | - | 次の区画を固定順で解放 |

### 約定順序

1. 各プレイヤーの `market` 配列を先頭10件に切る。
2. 注文index 0同士、index 1同士、という順で両者を組み合わせる。
3. `HIRE` と `BUY_LAND` はatomic注文としてplayer 0、player 1の順で処理する。
4. 売買注文は1個ずつ価格を提示する。
5. 同じ単位では、両者が更新前の同じ市場在庫から価格を得る。
6. player 0、player 1の順に約定を反映する。
7. 両者の単位処理後、次の1個へ進む。
8. 注文index全体の処理後に表示価格を更新する。

したがって、`SELL item 100` の100個が同じ価格で売れるわけではない。1個ごとに在庫と次の約定価格が変わり、Shed在庫が尽きれば注文の残りは停止する。

- 売却価格が1の場合、その売却分は市場在庫を増やさない。
- `BUY_PRODUCT` は購入後在庫に対する価格を使い、変更のない市場で即売買して利益が出ないようにしている。
- 現金不足やShed満杯で失敗すると、その注文の残り数量は処理されない。

## 12. Town需要とShop

Town Centerはデフォルトで24stepごと、すなわち1日1回、FERTILIZER以外の全商品を市場在庫から1個ずつ消費する。日数経過による2倍・4倍需要は存在しない。

Shopは3日ごとに1件解放され、最大8件。復元抽出なので同じShopが複数回選ばれる。各インスタンスは4stepごとに独立して商品を消費する。

| Shop | 消費商品 |
|---|---|
| BAKERY | EGG, WHEAT |
| PIZZA_SHOP | MILK, TOMATO, WHEAT |
| BRUNCH_SPOT | EGG, WHEAT, STRAWBERRY |
| YARN_STORE | WOOL×2 |
| ICE_CREAM_SHOP | STRAWBERRY, MILK, WHEAT |
| PET_CAFE | CARROT×2 |
| SMOOTHIE_SHOP | STRAWBERRY, MILK |
| FARMERS_MARKET | WHEAT, CARROT, TOMATO, STRAWBERRY |

単一商品Shopは1tickに2個、それ以外は各対象商品を1個ずつ消費する。Shop数は時間とともに単調増加するが、構成はseedごとに異なる。

## 13. 雑草と乱数

毎日終了時、空いている解放済みtileごとにデフォルト0.5%の確率で雑草が発生する。

日次乱数はepisode seedとdayから決定的に作られるが、各農場の空tile数に応じて乱数消費数が変わる。先に処理される農場の状態が、その後の農場の雑草判定や同日のShop抽選に影響し得る。

記録済み行動を別の自分の戦略と組み合わせて再生すると、空tile数が変わってShop系列まで変化する場合がある。Replayベースの比較では、元ゲームとShop系列が一致した試合を分けて評価する必要がある。

## 14. 実装時のsilent no-opチェックリスト

エージェントは少なくとも次をaction生成前に検証する。

- 移動先が盤内か
- tileがLOCKEDでないか
- `PLANT` 対象が空で、種が足りているか
- 同一ターンの作物別 `PLANT` 総数が種数以内か
- 当日すでに `WATER`、`FEED`、`CARE` 済みでないか
- `HARVEST` の収量が正で、作物が初回収穫日以降か
- `FERTILIZE` 用の肥料を作業員が所持しているか
- 動物と施設種別が一致しているか
- `PICKUP`、`DROP`、Shed向け `PLACE` がShedアクセス地点で行われるか
- 市場で売る商品がShed内にあるか
- Shedに購入品を受け入れる容量があるか
- `hands` actionのindexと現在のhands数が一致しているか

## 15. 戦略実装への直接的な含意

- 植えた日には必ず水をやる。
- CAREは同日給餌と組み合わせる。
- 肥料は有効期間が生産日と重なるように使う。
- 複数stepの `PICKUP → 移動 → FEED/PLACE` を途中で中断しない。
- 最終報酬は現金のみなので、終了前にShed在庫を売却する。
- 大量売却は注文時価格×数量で評価せず、1個ずつの約定を再現する。
- Shop構成と市場在庫を見て、CARROT、TOMATO、EGGの不足価格を利用する。
- ローカル評価は同じseedを両seatで実行し、Shop系列の変化も記録する。
- 提出前に、ローカル環境とKaggle側のエンジンバージョンを再確認する。
